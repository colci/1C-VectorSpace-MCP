# План реализации RAG для 1С конфигурации (Qdrant + MCP Server)

Этот документ описывает план создания системы семантического поиска и предоставления контекста по структуре и коду конфигурации 1С:УНФ с использованием векторной базы данных Qdrant и протокола Model Context Protocol (MCP).

---

## 1. Стратегия чанкинга (нарезки) данных 1С

Выгрузка конфигурации 1С состоит из двух основных типов файлов:
1. **XML-файлы описания метаданных** (структура справочников, документов, регистров и т.д.).
2. **BSL-файлы программного кода** (модули объектов, менеджеры, общие модули, модули форм с расширением `.bsl`).

Обычный текстовый чанкинг (по размеру окна) для исходного кода и метаданных малоэффективен, так как он разрывает логические конструкции (функции, процедуры) и теряет связи. Мы применим **структурный семантический чанкинг**.

### А. Чанкинг BSL-кода (по процедурам и функциям)
Каждый программный модуль (`.bsl` файл) парсится на отдельные методы:
* **Границы чанка:** Начало метода (`Процедура` / `Функция`) и его конец (`КонецПроцедуры` / `КонецФункции`).
* **Метаданные чанка (Payload):**
  * `module_path` (например, `CommonModules.RFIDКлиент`)
  * `module_type` (например, `CommonModule`, `ObjectModule`, `ManagerModule`, `FormModule`)
  * `method_name` (например, `ЗаписатьДанныеВRFID`)
  * `is_export` (экспортный метод или локальный)
  * `file_path` (абсолютный или относительный путь к файлу)
  * `lines` (диапазон строк в исходном файле, например `57-120`)
* **Контекст чанка (Text to Embed):**
  Перед телом функции добавляется заголовочный контекст, чтобы модель эмбеддингов лучше понимала область видимости:
  ```text
  Модуль: ОбщийМодуль.RFIDКлиент
  Метод: ЗаписатьДанныеВRFID (Экспортный)
  Код:
  Процедура ЗаписатьДанныеВRFID(Результат, Параметры) Экспорт
      // [Тело метода...]
  КонецПроцедуры
  ```

### Б. Чанкинг XML-метаданных
Вместо индексации сырого XML, мы будем генерировать краткое структурированное текстовое описание (карточку объекта) на основе XML:
* **Что извлекаем из XML:** Имя объекта, синоним, список реквизитов (имя, тип, синоним, пояснение), список табличных частей, связанные формы.
* **Пример формируемого текста чанка:**
  ```text
  Справочник: Номенклатура (Catalogs.Номенклатура)
  Синоним: Номенклатура
  Описание: Хранит информацию о товарах, услугах и работах.
  Реквизиты:
    - Артикул (Строка, 25): Код производителя или артикул товара
    - ВидНоменклатуры (СправочникСсылка.КатегорииНоменклатуры): Категория товара
    - СтавкаНДС (СправочникСсылка.СтавкиНДС): Основная ставка НДС
  Табличные части:
    - Характеристики (Характеристика, Штрихкод)
  ```
* **Метаданные чанка (Payload):**
  * `object_type` (`Catalog`, `Document`, `InformationRegister`, и т.д.)
  * `object_name` (`Номенклатура`)
  * `file_path` (путь к XML)

## 2. Схема коллекции Qdrant

Мы создадим коллекцию `1c_unf_configuration` со следующими параметрами:
* **Размерность вектора:** Зависит от модели эмбеддингов (например, 1536 для `text-embedding-3-small` от OpenAI или 1024 для `multilingual-e5-large`).
* **Метрика расстояния:** `Cosine` (косинусное сходство).
* **Payload-индексы** для быстрой фильтрации:
  * Индекс на поле `module_type` (keyword)
  * Индекс на поле `object_type` (keyword)
  * Индекс на поле `method_name` (text/keyword)

## 3. Архитектура MCP-сервера

MCP-сервер будет написан на **Python** (с использованием официального `mcp` SDK) и будет предоставлять AI-ассистенту инструменты для работы с кодовой базой 1С.

### Доступные инструменты (Tools):
1. **`search_code`**: Семантический поиск по коду модулей (BSL) с возможностью фильтрации по типу модуля или имени метода.
   * *Параметры:* `query` (строка), `limit` (число), `module_type` (опционально).
2. **`search_metadata`**: Семантический поиск по структуре метаданных (XML) для поиска нужных реквизитов или табличных частей объектов.
   * *Параметры:* `query` (строка), `limit` (число), `object_type` (опционально).
3. **`get_method_code`**: Получение полного исходного кода конкретного метода по пути.
   * *Параметры:* `module_path` (например, `CommonModules.RFIDКлиент`), `method_name` (`ЗаписатьДанныеВRFID`).
4. **`get_module_structure`**: Получение списка всех процедур/функций модуля с их описаниями.
   * *Параметры:* `module_path`.

## 6. Развитие системы: Графовая база данных (Этап 2)

После успешного запуска векторного RAG планируется расширение системы до гибридной схемы **GraphRAG** для точного анализа взаимосвязей и зависимостей конфигурации 1С.

### Подход "Graph Light" (Упрощенный граф)
Для минимизации инфраструктурных затрат (без развертывания серверов вроде Neo4j):
1. **Сбор связей при индексации:** Скрипт `index_config.py` при парсинге XML-файлов метаданных будет собирать зависимости (например, связь *"Документ X содержит реквизит типа Справочник Y"* или вызовы общих модулей в BSL-коде).
2. **Интеграция в Qdrant:** Эти связи будут записываться в текстовом виде непосредственно в карточки объектов и BSL-чанки, а также сохраняться в локальный JSON-файл связей проекта.
3. **MCP-инструмент:** В MCP-сервер будет добавлен инструмент `get_dependencies`, позволяющий модели мгновенно получать граф зависимостей для конкретного объекта метаданных.

### Полноценный граф (Перспективный этап)
Если потребуется глубокий анализ цепочек вызовов (Call Graph) на уровне абстрактного синтаксического дерева (AST) языка BSL, будет рассмотрено подключение легковесной графовой базы данных (например, Memgraph или FalkorDB) с поддержкой запросов Cypher для автоматического выявления влияния изменений (Impact Analysis) в коде 1С.

## 7. Развитие системы: Вынесение настроек внешних моделей эмбеддингов (Перспективный этап)

Для повышения гибкости и переносимости системы RAG планируется абстрагировать и вынести настройки внешних API для генерации эмбеддингов:
1. **Поддержка альтернативных провайдеров:** Реализовать поддержку не только OpenAI и локального FastEmbed, но и других внешних сервисов эмбеддингов (например, Ollama, Cohere, Hugging Face API, Yandex GPT/Embeddings) через единый унифицированный интерфейс (класс-обертку).
2. **Параметризация через конфигурационный файл:** Все ключи доступа, URL-адреса хостов, названия моделей и параметры лимитов (размерность векторов, таймауты, прокси) должны быть полностью перенесены в `.env` и загружаться динамически без хардкода в скриптах индексации и MCP-сервера.
