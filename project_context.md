## 1. Цель проекта
Создать локальную систему RAG (Retrieval-Augmented Generation) для конфигураций 1С на основе векторной базы данных Qdrant и предоставить доступ к ней для LLM через MCP-сервер (Model Context Protocol).

## 5. Важные проектные решения и договоренности
*   **Поэтапный подход к графовой базе данных (GraphRAG):** 
    *   **Этап 1 (Текущий):** Полноценная графовая СУБД (например, Neo4j) не используется, чтобы избежать усложнения инфраструктуры. Все усилия направлены на запуск чистого векторного RAG на базе Qdrant, который покроет 80% задач разработки.
    *   **Этап 2 (Graph Light):** Будет реализован легкий анализ зависимостей. Скрипт индексации при парсинге XML соберет структуру связей в JSON-файл, а MCP-сервер получит инструмент `get_dependencies` для выдачи связей ИИ-модели.
    *   **Этап 3 (Полноценный граф):** При необходимости глубокого анализа цепочек вызовов (Call Graph) на уровне AST-дерева языка BSL будет развернута графовая база данных (например, Memgraph или FalkorDB) с поддержкой Cypher.

*   **Чанкинг кода:** Строго по границам процедур и функций (`Процедура ... КонецПроцедуры`), с добавлением заголовочного контекста (имя модуля, тип модуля, экспортность).

*   **Гибкая настройка эмбеддингов (Перспективный этап):** Планируется вынести все параметры внешних моделей и API (OpenAI, Ollama, Cohere, Hugging Face, Yandex) в файл конфигурации `.env` and создать единую обертку (интерфейс) для переключения между провайдерами эмбеддингов без правки кода.
